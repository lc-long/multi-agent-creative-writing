## 1. 项目概述

### 1.1 项目名称

多Agent创意写作系统（Multi-Agent Creative Writing System）

### 1.2 项目目标

构建一个基于多Agent协作的创意写作系统，通过不同专业背景的AI Agent协作，生成比单一AI更有创意、更完整的故事内容。

### 1.3 核心价值主张

```
单Agent = 一个"聪明人"独立思考
多Agent = 多个"不同背景的人"协作讨论
```

**核心价值：** 多元视角碰撞产生更好的结果

## 2. 用户故事（User Stories）

### 2.1 用户角色

| 角色 | 描述 | 核心需求 |
|------|------|---------|
| 编剧 | 影视/动画编剧 | 快速获得故事大纲和剧本结构 |
| 小说家 | 网文/传统作家 | 获得角色设定和情节灵感 |
| 游戏策划 | 游戏剧情设计 | 获得世界观设定和角色关系 |
| 内容创作者 | 自媒体/短视频 | 快速获得创意内容框架 |

### 2.2 用户故事列表

```
作为 [内容创作者/编剧/小说家]
我想要 [多个AI专家协作帮我构思故事]
以便 [获得比单一AI更有创意、更完整的故事方案]
```

**具体用户故事：**

| 编号 | 用户角色 | 用户故事 | 验收标准 |
|------|---------|---------|---------|
| US-01 | 编剧 | 我想输入一个主题，获得完整的故事大纲 | 输出包含起承转合的结构化大纲 |
| US-02 | 小说家 | 我想看到不同角色之间的对话示例 | 输出符合角色性格的对话 |
| US-03 | 游戏策划 | 我想获得世界观设定文档 | 输出自洽的世界观设定 |
| US-04 | 创作者 | 我想看到各个专家的讨论过程 | 可以看到每个agent的观点和讨论 |
| US-05 | 编剧 | 我想导出生成的内容 | 支持Markdown/PDF导出 |
| US-06 | 创作者 | 我想对生成的内容进行修改 | 支持迭代修改功能 |

## 3. 功能需求（Functional Requirements）

### 3.1 核心功能

| 编号 | 功能名称 | 功能描述 | 优先级 |
|------|---------|---------|-------|
| FR-01 | 用户输入 | 用户输入故事主题/设定/约束条件 | P0 |
| FR-02 | 故事大纲生成 | 生成包含起承转合的结构化大纲 | P0 |
| FR-03 | 角色设定生成 | 生成角色卡片（性格、背景、动机） | P0 |
| FR-04 | 对话生成 | 生成符合角色性格的对话示例 | P0 |
| FR-05 | 世界观生成 | 生成世界观设定文档 | P0 |
| FR-06 | 讨论过程展示 | 用户可查看Agent间的讨论过程 | P1 |
| FR-07 | 迭代修改 | 用户可对输出进行修改和重新生成 | P1 |

### 3.2 扩展功能

| 编号 | 功能名称 | 功能描述 | 优先级 |
|------|---------|---------|-------|
| FR-08 | 多类型支持 | 支持科幻、奇幻、现实等多种故事类型 | P2 |
| FR-09 | 导出功能 | 支持导出为Markdown/PDF格式 | P2 |
| FR-10 | 历史记录 | 支持历史记录和版本管理 | P3 |

### 3.3 功能详细说明

#### FR-01 用户输入

**输入项：**
- 故事主题（必填）：如"未来世界的AI觉醒"
- 故事类型（选填）：科幻、奇幻、现实、悬疑、爱情等
- 其他约束（选填）：目标字数、目标受众、特定元素等

**输入示例：**
```
主题：未来世界的AI觉醒
类型：科幻
约束：适合青少年阅读，包含哲学思考
```

#### FR-02 故事大纲生成

**输出结构：**
```yaml
title: 故事标题
genre: 故事类型
synopsis: 一句话简介
acts:
  - name: 开篇
    description: 故事起始，引入主角和世界
    key_events: [事件1, 事件2]
  - name: 发展
    description: 冲突升级，主角面临挑战
    key_events: [事件1, 事件2]
  - name: 高潮
    description: 故事高潮，主角做出关键选择
    key_events: [事件1, 事件2]
  - name: 结局
    description: 故事收尾，冲突解决
    key_events: [事件1, 事件2]
themes: [主题1, 主题2]
```

#### FR-03 角色设定生成

**输出结构：**
```yaml
characters:
  - name: 角色名
    role: 主角/配角/反派
    age: 年龄
    personality: 性格描述
    background: 背景故事
    motivation: 核心动机
    arc: 成长弧线
    relationships:
      - character: 其他角色名
        relation: 关系描述
```

#### FR-06 讨论过程展示

**展示内容：**
- 每个Agent的初始方案
- Agent之间的讨论记录（3轮）
- 最终达成的共识
- 记录的分歧点（如有）

## 5. 业务流程

### 5.1 主流程

```
┌─────────────────────────────────────────────────────────────┐
│                    用户输入阶段                               │
├─────────────────────────────────────────────────────────────┤
│  用户输入: 主题 + 类型 + 其他约束                              │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    Agent协作阶段                              │
├─────────────────────────────────────────────────────────────┤
│  第一轮: 各Agent独立提出方案                                   │
│    ├─ 剧情Agent: 故事结构方案                                 │
│    ├─ 人物Agent: 角色设定方案                                 │
│    ├─ 对话Agent: 对话风格建议                                 │
│    └─ 世界观Agent: 世界观设定方案                              │
│                                                              │
│  第二轮: 互相Review和讨论 (3轮)                                │
│    ├─ 各Agent阅读其他Agent的方案                               │
│    ├─ 提出修改建议和反对意见                                    │
│    └─ 达成共识或记录分歧                                       │
│                                                              │
│  第三轮: 整合输出                                             │
│    └─ 合并所有方案，生成最终输出                                 │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    输出展示阶段                               │
├─────────────────────────────────────────────────────────────┤
│  展示:                                                      │
│    ├─ 故事大纲 (起承转合)                                     │
│    ├─ 角色设定 (人物卡片)                                     │
│    ├─ 示例对话                                               │
│    ├─ 世界观设定                                             │
│    └─ Agent讨论过程 (可展开查看)                               │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    迭代优化阶段                               │
├─────────────────────────────────────────────────────────────┤
│  用户可以:                                                   │
│    ├─ 对某个部分提出修改意见                                    │
│    ├─ 要求重新生成某个部分                                     │
│    └─ 保存/导出最终结果                                       │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 Agent协作流程

```
用户输入主题
      ↓
Orchestrator接收
      ↓
┌─────────────────────────────────────────────┐
│           第一轮：独立提案                    │
├─────────────────────────────────────────────┤
│  剧情Agent ──→ 故事结构方案                  │
│  人物Agent ──→ 角色设定方案                  │
│  世界观Agent ──→ 世界观设定方案              │
│  对话Agent ──→ (等待其他Agent输出)           │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│           第二轮：讨论 (3轮)                  │
├─────────────────────────────────────────────┤
│  轮次1: 各Agent阅读并反馈                    │
│  轮次2: 根据反馈调整方案                      │
│  轮次3: 最终确认和整合                        │
└─────────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────────┐
│           第三轮：输出整合                    │
├─────────────────────────────────────────────┤
│  对话Agent ──→ 生成对话示例                  │
│  合并所有输出 ──→ 最终故事方案                │
└─────────────────────────────────────────────┘
      ↓
返回用户
```

## 8. 验收标准（Acceptance Criteria）

### 8.1 功能验收

```gherkin
Feature: 故事生成

  Scenario: 用户输入科幻主题
    Given 用户输入主题"未来世界的AI觉醒"
    And 用户选择类型"科幻"
    When 系统完成生成
    Then 系统应输出完整故事大纲
    And 系统应输出至少3个角色设定
    And 系统应输出至少1段示例对话
    And 系统应输出世界观设定
    And 生成时间应小于60秒

  Scenario: 查看讨论过程
    Given 系统正在生成故事
    When 用户点击查看讨论过程
    Then 系统应显示每个Agent的观点
    And 系统应显示Agent之间的讨论记录

  Scenario: 迭代修改
    Given 系统已生成故事
    When 用户对角色设定提出修改意见
    Then 系统应根据修改意见重新生成角色设定
    And 其他部分保持不变或相应调整
```

### 8.2 性能验收

| 指标 | 目标值 | 测试方法 |
|------|-------|---------|
| 生成时间 | < 60秒 | 测量3次取平均值 |
| API成本 | < ¥1/次 | 统计10次取平均值 |
| 界面响应 | < 100ms | 用户操作响应时间 |

## 9. 项目范围

### 9.1 包含（In Scope）

- 4个Agent的协作生成故事
- 基础的Web界面
- 查看讨论过程功能
- 导出Markdown格式

### 9.2 不包含（Out of Scope）

- 用户注册登录（V1不做）
- 历史记录云同步（V1不做）
- 多语言支持（V1不做）
- 移动端适配（V1不做）

## 10. 约束和假设

### 10.1 约束

- 使用OpenAI兼容的API接口
- 前端使用React/Next.js
- 后端使用Python
- 部署在本地或云服务器

### 10.2 假设

- 用户有可用的OpenAI API Key
- 用户网络环境可以正常访问API
- 用户具备基本的计算机操作能力

## 11. 风险和依赖

### 11.1 风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| API成本超预算 | 高 | 中 | 设置token限制，优化prompt |
| 生成质量不稳定 | 高 | 中 | 多轮测试，优化prompt |
| Agent协作效果差 | 中 | 中 | 设计有效的讨论机制 |

### 11.2 依赖

- OpenAI API可用性
- 稳定的网络环境
- 前端开发环境
